# Firestore Security Rules Unit Tests

This directory contains automated unit tests and property tests for the project's Firestore security rules (`firestore.rules`), executed against the local Firebase Firestore Emulator.

## Running Locally

Prerequisites:
- Node.js 20+
- Java 21+ (required by Firebase Emulator)

From this directory (`firestore_rules_test/`), run:

```bash
npx firebase emulators:exec --only firestore --project demo-dnd5e "npm test"
```

The tests run strictly against a `demo-` project ID and the local emulator, ensuring no live project data is ever touched.

## App Check

Firebase App Check (reCAPTCHA Enterprise, restricted to the production domain) is enforced directly at the Firebase API gateway / console layer prior to rules execution. It is not visible to or evaluated within Firestore security rules.

## Test Suites

1. `h1_to_h11.test.js`: Direct regression verification of exploit invariants H1 through H11, along with legacy player join controls.
2. `host_proof_law.test.js`: Verification of the write-only proof document protocol (`rooms/{roomCode}/hostProof/current`), including a property test across 320+ candidate keys.
3. `lobby_update_law.test.js`: Property law test across 500 pseudorandom seeds verifying update invariants and state preservation.
4. `write_sites_and_golden.test.js`: Verification of all client write payloads across application services and adapters, including golden fixtures generated by Dart domain models.
5. `legacy_shapes_and_privilege.test.js`: Verification of hosted and hostless legacy campaign shapes carrying ledger keys, and least-privilege denial on unknown collections and subcollections.
