## 🛡️ Core Engineering Directives

### 0. Prime Directive: Clean Room Architecture & Zero Third-Party Tool (5etools) Coupling
- **Absolute Decoupling from 5etools & Proprietary Schemas:** The codebase MUST NOT contain hardcoded third-party site keys (e.g., 5etools bundle lists like `monsterfluff`, `racefluffmeta`, `subclassfeature`), third-party naming conventions, or splatbook identifiers in core business logic.
- **Agnostic Structural Anti-Corruption Layer (ACL):** All remote repository and JSON ingestion (`GithubIngestorAdapter`) must recursively traverse incoming payloads using generic structural indicators (`name`, `entries`, `hitDie`, `stats`, `type`, `level`, actions) rather than coupling to third-party tool bundle schemas. All external pipe-delimited syntax (`Feature|Class|Source|Level`, `Spell|Source#c`) is strictly isolated into dedicated infrastructure ACL parsers (`CompendiumPipeParser`).
- **Capability-Driven `FeatureGrant` Mechanics:** Combat calculations, attack ability substitutions, and capability resolutions MUST NOT use string pattern-matching against non-SRD classes, subclasses, or feats (`battle smith`, `hexblade`, `medium_armor_master`, `observant`, `alert`). Mechanics MUST evaluate pure data attributes: domain `FeatureGrant`s (`GrantType.attackAbilitySubstitution`, `GrantType.capabilityFlag`, `GrantType.acFormula`) or normalized capability flags (`flags['initiativeBonusMode']`, `flags['mediumArmorDexCapBonus']`, `flags['passivePerceptionBonus']`).

### 1. Hexagonal Architecture & Domain Purity
- **Zero Flutter in Domain:** Files in `lib/domain/` MUST NOT import `package:flutter/...`. Use `package:meta/meta.dart` for annotations like `@immutable`.
- **Enforced via Automated Test:** `test/domain/domain_purity_test.dart` automatically audits `lib/domain/` on every CI run.
- **Infrastructure DTO Purity:** Files in `lib/infrastructure/dtos/` MUST NOT import `package:flutter/...`. Use pure `package:meta/meta.dart` for `@immutable` annotations to preserve decoupling from the Flutter engine runtime. Verified by `test/infrastructure/dtos/dto_purity_test.dart`.
- **Core Package Self-Containment (`vtt-engine-core` Readiness):** `lib/domain/` is 100% self-contained with zero imports pointing outside `lib/domain/` (zero `../../models/` imports, zero `package:flutter/`, zero application/infrastructure leaks). All domain models (`CharacterDraft`, `EntityReference`, `FeatureGrant`, `Character`, `LootContainer`, `Spell`, `Monster`, `EquipmentItem`, `CoreTypes`, `Condition`, `PartyEvent`, `RoomRoll`) reside in `lib/domain/models/`. Backward compatibility is preserved via re-export barrels in `lib/models/`. Enforced via `test/domain/domain_purity_test.dart`.
- **Ports & Adapters:** Define abstract interfaces in `lib/domain/ports/`. Implementations live in `lib/infrastructure/repositories/` and `lib/infrastructure/adapters/`.
- **Domain Purity of Transport Ports:** `IP2pTransportPort` and all interfaces in `lib/domain/ports/` must import pure domain contracts (e.g., `TransportState` in `lib/domain/ports/transport_state.dart`) rather than application services (`CascadingTransportRouter`) or infrastructure DTOs (`CharacterTelemetryDto`), strictly preserving the Dependency Inversion Principle.
- **Immutability:** All domain models and value objects must have `const` constructors and `copyWith()` mutators. Never expose mutable lists or maps directly.

### 2. Decentralized State, CvRDT & P2P Networking Directives
- **Hybrid Logical Clock (HLC):** Implements `Comparable`. When physical timestamps (`l`) and counters (`c`) collide, use `nodeId` (device ID string) as the deterministic lexicographical tie-breaker. Random tie-breakers are strictly forbidden.
- **Cryptographic Node Identity Enforcement & Uniformity:** Orchestrators and services stamping CRDT registers (`HomebrewImportOrchestrator`, `PartyRoomService`) must generate pure cryptographically secure UUID v4 fallback identifiers (`const Uuid().v4()`) rather than physical wall-clock timestamps or prefixed strings to guarantee HLC tie-breaker determinism across simultaneous offline mesh imports. Dynamic node IDs must be resolved once and shared uniformly with internal HLC instances.
- **Clock Spoofing & Skew Mitigation:** Network time synchronization via `INetworkTimePort` and `ClockSyncService` computes physical clock offsets (`offsetMs`). Fallback message queries (`FirebaseFallbackAdapter`) buffer queries by 30 seconds into the past to tolerate physical device clock skew, and enforce bounded SHA-256 payload hash LRU deduplication caches (`_processedPayloadHashes`, max 500 entries) cleared upon disconnection to prevent hash/message ID poisoning.
- **Observed-Remove Set (`CrdtOrSet`):** Deletions create tombstones. Always implement `prune(threshold)` to prevent memory leaks from unbounded tombstone accumulation. Internal items and tombstones maps are strictly sealed via `Map.unmodifiable()` across constructors (`CrdtOrSet`, `const CrdtOrSet.empty()`) and mutator operations (`addBatch`, `remove`, `merge`, `pruneTombstones`). Bulk additions MUST use `addBatch` to eliminate $O(N^2)$ map re-allocations. `remove()` unconditionally records a tombstone (preventing out-of-order add revivals). Obsolete tombstones older than active items are suppressed on merge to preserve commutativity ($A \sqcup B = B \sqcup A$).
- **LWW Register (`CrdtLwwRegister`):** Modifications return a new immutable instance.
- **Minion Immutability in CRDT Collections & Zero Silent Mutations:** Minions and summon entities (`AnimatedObjectInstance`) within `CampaignProfile.roomState.activeMinions` are strictly immutable domain entities. All deprecated in-place mutating methods (`takeDamage`, `heal`, `applyHeal`, `grantTempHp`) and silent empty setters are eradicated. Modifications MUST strictly utilize pure copy-transform methods (`applyDamage`, `applyHealing`, `applyTempHp`).
- **Strict Network Time Injection & Authoritative Milestone Pruning:** Prune tombstones via `RoomStateReconciliationService.executeMilestonePrune` using authoritative server/ledger timestamps, decoupled from unverified local clock estimations. `RoomStateReconciliationService` requires constructor injection of `networkTimeProvider` (sourced from `ClockSyncService.currentNetworkTimeMs`), eliminating local wall-clock spoofing vulnerabilities during pruning. When extreme local clock skew would invert pruning horizons ($threshold \ge networkTime$), pruning is deferred gracefully (`safePrune`).
- **Host Buffered Milestone Pruning Horizon:** Host milestone flushes (`executeHostMilestoneFlush`) buffer the pruning horizon by subtracting twice the heartbeat TTL (`2 * heartbeatTtl`) from network-synchronized physical time, preserving tombstones for peers experiencing transient reconnects while safely purging ancient tombstones.
- **Field-Level Sub-Resource Reconciliation (`RoomStateReconciliationService.reconcileProfile`):** Base room state is hydrated from snapshot milestones, with incremental CRDT deltas reconciled on top via `RoomStateReconciliationService`. Rather than whole-document LWW overwrite of `CampaignProfile` upon receiving `room_sync_full` payloads, state convergence merges sub-resources independently (notes via `CrdtLwwRegister`, party purse via `PnCounter`, party rosters, active minions keyed by `m.id`, active encounters keyed by `participantId`, room metadata, and change logs). Concurrent edits to `notesRegister` resolve deterministically by favoring the higher HLC timestamp, logging the dropped delta to `changeLog` instead of unbounded string concatenation.
- **Echo Loop Prevention Mutex & Deep Model Equality:** `RoomSyncOrchestrator` synchronizes inbound packet handling using a formal `Mutex` lock (`_syncMutex.protect()`), eliminating boolean flag data races while ingesting and saving incoming network payloads. Entities participating in state broadcasts (`CampaignProfile`, `PartyPurse`) must implement value equality (`operator ==` and `hashCode`) to eliminate false-change broadcast triggers.
- **Narrow Mutex Critical Section & Asynchronous Ingress Persistence:** `RoomSyncOrchestrator` restricts `_syncMutex.protect()` strictly to in-memory state reconciliation, vector clock tracking, and CRDT joins. Disk persistence (`campaignRepo.saveProfileImmediate`) and subsequent repository event dispatches are executed decoupled *outside* the mutex lock, eliminating re-entrant mutex deadlocks and lock starvation. Outbound frames are stamped with monotonic sequence numbers and originating node IDs, suppressing self-echo loops and remote sync echo broadcasts.
- **Sliding Lookback Window & LinkedHashMap O(1) LRU Deduplication:** `RoomSyncOrchestrator` and `CascadingTransportRouter` enforce a 30-second sliding lookback window and an in-memory 500-entry `LinkedHashMap<String, bool>` LRU cache tracking payload SHA-256 digests. This guarantees $O(1)$ amortized lookup, removal, and re-insertion for exact duplicate suppression and packet jitter tolerance, exposing `Set.unmodifiable(_processedPayloadHashes.keys)` for testing. Unknown or malformed payloads (`UnknownSyncMessage`) are discarded *before* updating the LRU cache to prevent cache-busting attacks and deduplication poisoning.
- **Asynchronous Stream Emission (Deadlock Prevention):** Reactive broadcast `StreamController`s across persistence repositories and transport services (including `LocalCampaignRepository`, `CascadingTransportRouter._stateController`, `CascadingTransportRouter._payloadController`, `RoomSyncOrchestrator._telemetryController`, `FirebaseFallbackAdapter`, `FirebaseSignalingAdapter`, and `LocalWifiAdapter`) MUST explicitly specify `sync: false`. Asynchronous microtask queue emission prevents re-entrant deadlocks when inbound network synchronization holds mutexes.
- **Asynchronous Microtask Payload Dispatch & Timer Teardown:** Inbound transport router payloads (`CascadingTransportRouter._handleIncomingPayload`) dispatch accepted payloads asynchronously via `scheduleMicrotask()` to prevent synchronous re-entrant `_syncMutex` deadlocks when adapters failover or receive inbound frames during broadcast execution stacks. Room re-initialization in `CascadingTransportRouter` must explicitly cancel and nullify prior heartbeat timers (`_heartbeatTimer`, `_fallbackHeartbeatTimer`) before activating new adapters.
- **WebRTC Async Microtask Dispatching:** In `WebRtcMeshAdapter`, `_incomingPayloadsController` is initialized with `broadcast(sync: false)` and DataChannel message arrivals in `_registerDataChannel` are dispatched via `scheduleMicrotask(() { if (!_incomingPayloadsController.isClosed) _incomingPayloadsController.add(text); })` to eliminate synchronous event-loop contention and prevent re-entrant mutex deadlocks.
- **4-Tier Waterfall & Dynamic Step-Up Recovery:** `CascadingTransportRouter` cascades through Tier 1 (Local Wi-Fi), Tier 2 (WebRTC Mesh), Tier 3 (Firebase Cloud Relay), Tier 4 (Offline). It enforces sequential failure thresholds (`sequentialFailureThreshold = 3`) and holdoff cooldowns (`stepUpHoldoff = 5s`) to dampen transport flapping. It periodically probes higher-tier adapters (`probeHigherTiers()`) via the polymorphic `IP2pTransportPort.probeViability()` contract, stepping up back to WebRTC when viable without downcasting.
- **WebRTC Signaling & Polite Glare Rollback:** WebRTC signaling state machine implements standard polite/impolite glare handling. When signaling collisions occur (`have-local-offer` when receiving remote offer), the polite peer rolls back its local offer (`RTCSessionDescription('', 'rollback')`) and accepts the incoming offer. If rollback fails or throws on platform channels, it invokes `prunePeer(peerId)` and immediately initializes a clean `RTCPeerConnection` to accept the inbound offer without connection tear-down or split-brain channel loss.
- **Peer-Scoped Ephemeral Signaling Isolation & Readiness Gate:** `FirebaseSignalingAdapter` partitions tracked signaling documents by peer ID (`_peerTrackedDocPaths`). When an individual peer connection is established or opens its DataChannel, invoke `cleanUpPeerSignaling(peerId)` rather than wiping all room signaling documents (`cleanUpSignalingSession()`). In `WebRtcMeshAdapter`, ICE connection state transitions to `connected` defer ephemeral signaling document deletion until the peer DataChannel is fully open (`RTCDataChannelState.RTCDataChannelOpen`) or ICE state reaches `completed`. Document deletions enforce a 5-second timeout.
- **PN-Counter Currency Convergence & crdt_purse_delta Protocol:** Party currency denominations in `PartyPurse` converge using CvRDT `PnCounter` (positive and negative tracking per node ID), eliminating scalar Last-Write-Wins overwriting. Individual coin delta mutations (`PartyPurse.modifyCoin(denomination, delta, nodeId: id)`) dynamically route through positive/negative registers. All reductions calculate the delta against `effectiveCounter` and record negative decrements (`counter.decrement(nodeId, delta)`) rather than re-seeding with positive scalars. Profile reconciliation in `RoomStateReconciliationService._mergePartyPurse` unconditionally merges coin counters (`local.merge(remote)`) via CvRDT lattice join across all denominations. `RoomSyncOrchestrator` emits targeted high-frequency `crdt_purse_delta` payloads upon currency modifications and directly reconciles inbound purse deltas.
- **Scalar Priority, Lattice Join Idempotence & Vault Zero-Wipe Protection:** `PartyPurse.fromMap` prioritizes scalar coin denominations (`cp, sp, ep, gp, pp`) over stale PN-counters whenever scalars are present and differ from counter values, parsing across dynamic map types and applying deterministic deltas on `nodeId: 'cloud'` for lattice join idempotence ($A \sqcup A = A$). Adapters, transport layers, and non-currency campaign operations (`ensureRoomExists`, `joinCampaign`, `linkCharacterToCampaign`, `updateMemberPurse`, `updateCharacterRoster`) MUST NEVER transmit or overwrite `partyPurse` in Firestore, preventing shared balances from resetting to zero.
- **Vault Fund Dispersal vs External Loot:** Dispersing coins from the shared Party Vault reserve (`isVaultDispersal: true` via `PartyRoomService.disperseCoinsToParty` and `DisperseLootDialog.show`) is a zero-sum reallocation that MUST withdraw character shares from `partyPurse` via `withdrawCoins(...)`, strictly conserving total party wealth without monetary inflation. External loot hoards (`isVaultDispersal: false`) deposit reserve shares and remainders as newly discovered treasure.
- **Stateless Room Stub Rehydration & 30-Day Lease Auto-Renewal:** In stateless WebRTC and P2P mesh architectures, `PartyRoomService.joinCampaign()` inspects active subcollection presence (`rooms/{code}/nodes` and `rooms/{code}/relay_messages`) before concluding a room is missing, preventing false `"Campaign not found"` errors. Whenever any participant connects (host init, player join, or screen mount), `PartyRoomService.ensureRoomExists`, `FirebaseSignalingAdapter.initialize`, and `FirebaseFallbackAdapter.initializeRoom` rehydrate/touch `/rooms/{roomCode}` with `isStateless: true` and reset the 30-day lease (`expiresAt: now + 30 days`, `lastUpdated: now`) via `SetOptions(merge: true)`. Non-existent rooms without active presence or local DM keys continue to reject cleanly without generating phantom ghost records.
- **Firestore Security Rules & Campaign Lifecycle Management:** `firestore.rules` gracefully permits unverified App Check tokens (`isAppCheckVerified() { return true; }`), tolerates $\pm 24$-hour timestamp drift, validates non-negative coin bounds across `int` and `number`, permits 128-char node IDs and 1MB relays, and allows full room deletion. `PartyRoomService.syncAllExistingCampaignsToFirestore()` auto-syncs existing campaigns on `LandingScreen` mount. Confirmation-guarded Player Leave removes player/character in Firestore via `FieldValue.arrayRemove` and disposes dice streams; DM Delete verifies `hostKeyHash`, deletes `/rooms/{roomCode}`, and purges local state.
- **Outbox Resilience & Shared Character Storage:** `PartyRoomService.flushOutbox` aggregates all pending coin operations across the outbox batch into a single document write to avoid Firestore batch collision exceptions, increments `retryCount` on `PartyOutboxAction`, and purges poison pills after 3 consecutive failures to prevent infinite UI spinning. `session.sharedCharacters` stores the full `character.toMap()` payload (including `maxHp`, `currentHp`, `tempHp`, `armorClass`). UI consumers opening character sheets in party rooms check local persistent storage (`CharacterPersistenceService.getCharacter`) first before remote stubs, pushing updated telemetry back on route return. `LocalCharacterRepository` maintains zero unsynchronized in-memory caches, persisting immediately and synchronously mirroring to both Hive and `SharedPreferences`.

### 3. Dual-Ruleset Awareness (2014 RAW vs 2024 Revised)
- The engine supports both **2014 (SRD 5.1)** and **2024 (SRD 5.2.1)** D&D mechanics.
- Canonical `RulesetEdition` (`lib/domain/rules/ruleset_edition.dart`) serves as the pure domain enum with lossless adapters to legacy DTO enums (`DmRulesEdition`, `RulesetVersion`).
- Key differences:
  - Drinking Potions: Action (2014) vs Bonus Action (2024).
  - Exhaustion: 6 discrete tiers (2014) vs 10 linear -2 penalty steps (2024).
  - Counterspell: Spell save DC check (2014) vs CON saving throw by caster (2024).
  - Cure Wounds / Healing Word: 1d8/1d4 (2014) vs 2d8/2d4 (2024).
  - Divine Smite: Free trigger on hit (2014) vs Bonus Action concentration (2024).
  - Heavy Weapon / Power Attack & GWF: -5/+10 & reroll 1s/2s (2014) vs +PB damage & floor 3 (2024).
  - Weapon Masteries: Absent in 2014; active in 2024.
  - Subclass Milestones: 2014 varies by class (Level 1 Cleric/Sorcerer/Warlock, Level 2 Druid/Wizard, Level 3 others via `characterClass.getSubclassLevel(ruleset)`); 2024 standardizes all classes to Level 3.
  - Warlock Pact Magic: Uniform slot level (`pactMagicSlotLevel`), auto-upcasting lower-level spells, dynamic effect scaling (*Armor of Agathys*), distinct short-rest pool tracking.

### 4. Anti-Corruption Layer, Data Safety & Character Mechanics Directives
- **DTO Isolation & Safety:** Network/Disk JSON must map to DTOs in `lib/infrastructure/dtos/` before conversion to Domain models. Missing or malformed keys deserialize into safe tabletop defaults without uncaught exceptions. Always preserve unrecognized JSON keys in `unparsedPayload`. All numeric stats must be clamped (HP `0..999`, Level `1..20`, Ability Scores `1..30`, Currency `>= 0`). Computationally resolved fields take precedence over raw fallback keys.
- **Strict Entity Resolution & Anti-Collision:** Resolvers and codex lookups must prioritize exact `==` equality matches first. Substring fuzzy matching (e.g. `.contains('plate')`) is strictly prohibited to prevent collision regressions (such as Breastplate inheriting Full Plate AC 18). Fallbacks must enforce word-boundary regex (`\b`) and disallow binding generic tokens (e.g. `'Dragon'`) to distinct compound boss monsters (`'Dragon Turtle'`).
- **Compendium Deduplication & Clean Ingestion:** `SrdEquivalenceIndex` indexes base SRD libraries unpolluted by custom homebrew. Batch imports drop canonical SRD duplicates (`excludeSrdCanon: true`), route `baseitem`/`magicvariant` to items and `subrace` to races, format markdown tables and deities, and persist re-parsed data to both Hive and SharedPreferences.
- **Innermost Tag Resolution & Table Formatting:** `EntryNodeTransformer` and `CompendiumJsonIngestionPipeline.cleanRawTags` resolve innermost tags first using `[^{}]+` within a bounded loop (`passes < 10`) to cleanly process nested callout notes (`{@note ... {@spell contagion}}`). Table cells and column headers in `customProperties.rows` and `colLabels` are automatically cleaned to prevent raw unrendered tags in rollable table cards and markdown tables.
- **Rolling vs Data Table Differentiation & Tabular UI Rendering:** Compendium tables are classified into Rollable Tables (`tables`) vs Data Tables (`dataTables`) via `isRollingTable`. Both types sync to `DmScreenLibrary` and appear in the Rules Compendium with interactive filter chips. Markdown tables (`| ... |`) inside cards (`DmRuleCard`, `ItemCard`, `FeatCard`, `SpellCard`, `RaceCard`) are rendered as native, horizontally scrollable Flutter `Table` widgets via `FormattedMarkdownText` / `ScrollableMarkdownTable`. Table containers wrap in `ScrollConfiguration` with touch, mouse drag, trackpad, and stylus devices, providing an interactive `Scrollbar` with visible thumb/track and rounded clipping (`ClipRRect` and `PressableCard.clipBehavior: Clip.antiAlias`) so wide tables never overflow or break card layouts, allowing seamless left-to-right scrolling without triggering card tap actions.
- **Universal Compendium & Codex Markdown Formatting (`FormattedMarkdownText`):** All compendium cards and detail dialogs (`ItemCard`, `ItemDetailDialog`, `SpellCard`, `SpellComparisonDialog`, `CreatureStatBlockDialog`, `FeatCard`, `HomebrewStudioScreen`, `CharacterBuilderScreen`, `AddFeatDialog`) MUST use `FormattedMarkdownText` to render formatted descriptions and embedded tables. Card previews support `maxLines` and `overflow` (`TextOverflow.ellipsis`).
- **Subclass Feature Propagation, Ingestion Stitching & Subclass Disambiguation:** Individual subclass features (`subclassFeature` records possessing `subclassShortName`, `gainSubclassFeature`, or category hints) are strictly disambiguated from full `Subclass` domain entities across `GithubIngestorAdapter._inferEntityType`, `CompendiumJsonIngestionPipeline._ingestSingleEntityMap`, and `HomebrewEntityDto._detectEntityType`. Subclass features register into `SrdClassesLibrary` for relational AST stitching and into `otherEntries`, and are strictly excluded from `customSubclasses` and `allSubclasses` to prevent feature fragmentation in compendiums and the character builder. `CompendiumClassParser.parseSubclass` cleanly strips compendium source pipes (`Warlock|PHB` -> `warlock`), infers missing parent classes from `subclassFeatures` / entries pipes (`Tentacle of the Deeps|Warlock|...`), and falls back to standard tabletop class slug prefixes. In `SrdClassesLibrary`, `allClasses` matches subclasses by normalized clean slugs (`_classSlugsMatch`) and prefix matching (`$cleanClassSlug-`), preventing dropped homebrew/compendium archetypes. In compendiums, milestone features referencing child abilities through pointer nodes (`refSubclassFeature`, `refClassFeature`) or choice structures in `options`/`list` blocks are recursively expanded via `CompendiumClassParser._expandFeatureAst`, elevating feature pointers to standalone milestone headers (`### FeatureName (Level X)\n*SubclassName Feature*`) and inlining choices into sub-sections (`#### OptionName\n\n<rules text>`). In `AbilitiesAndTraitsTab`, `FeaturesTraitsSection`, and `CharacterActionsResolver`, subclass resolution queries `SrdClassesLibrary.findSubclass` and falls back directly to `cls.subclassRef.customProperties['featuresMarkdown']`. 2014 Level 1 milestone evaluation (Warlock, Cleric, Sorcerer) activates at Level 1 even when parent class metadata is unhydrated.
- **Subrace Attribute Replacement, Lineage Spells & Flexible Lineage Architecture:** `Subrace` preserves all mechanical attributes. `CompendiumRaceParser.parseSubrace` normalizes ability keys to standard lowercase names and extracts skills, tools, and bonus spells. In 2014 mode, subrace attributes REPLACE base species attributes: ability score increases, speed, and darkvision replace base species values. Innate cantrips and spells from subraces/species (`SkillTraitResolver.getInnateSpeciesSpells`) auto-register upon character finalization, and subrace skill proficiencies pass to `SkillTraitResolver.resolveSkills` with collision detection. Descriptions are rendered using `FormattedMarkdownText` with structured attribute badges. Subrace flexible choices are bounded by `flexibleAbilityPool`. When stats precede species (`attributesFirst`), selecting a flexible lineage renders inline choices with live attribute totals and gates progression.
- **2014 Background Compilation & Starting Equipment/Feature Injection:** In 2014 rules, backgrounds do not grant ASIs. `CompendiumBackgroundParser` agnostically parses arbitrary homebrew background skills from maps/lists and extracts narrative features from entries ASTs without hardcoded lists. `SrdBackgroundsLibrary.findBySlug` returns hydrated `Background` instances with canonical or arbitrary homebrew skill proficiencies, starting equipment items (`extractStartingEquipment`), and narrative background features (`get2014Feature`). During `CharacterFactory.buildFromDraft`, 2014 backgrounds grant skill proficiencies, instantiate starting equipment into `character.inventory`, and inject narrative features into `character.customProperties['backgroundFeature']` without polluting feats or generating background ASIs. `CharacterReparseEngine.reparse` self-heals both missing background skills and narrative features.
- **Compendium Class Starting Skills & Tool Proficiencies:** Class starting skill options (`startingProficiencies.skills`, `choose.from`, `any`, lists, `{@skill}` tags) are parsed via `CompendiumClassParser.parseClassSkills` into `CharacterClass.allowedSkills` and `skillChoiceCount`. `raw['proficiency']` contains saving throws, NOT starting skills. Class starting tools are parsed and granted via `FeatureGrant.bonusTool(...)` with growable list collections.
- **Character Sheet Reparse Engine & Self-Healing Migration:** `CharacterReparseEngine.reparse(Character)` provides deterministic, non-destructive re-parsing and state healing for existing characters in local persistence. It re-evaluates tool proficiencies, armor/weapon proficiencies, lineage spells, cleanses contaminated skill choice pools, resolves missing 2014 background features, self-heals un-hydrated subclass references (updating to canonical slugs and hydrating `featuresMarkdown` and `grants` into `customProperties`), and recomputes max HP while clamping current HP. `HomebrewPersistenceService.reparseAllHomebrew()` automatically triggers `CharacterPersistenceService().reparseAllCharacters()`. UI surfaces expose accessible reparse actions across AppBar sync buttons, character header chips, and roster card buttons.
- **5e RAW Value Object Healing & Instant Death Hardening:** `HitPoints` strictly decouples 0 HP unconsciousness (`isDowned => currentHp <= 0`) from permanent death (`isDead`). Standard healing (`heal(amount)`) revives downed actors at 0 HP per 5e RAW, while permanent death from massive damage (excess damage >= maxHp) requires explicit revival (`allowRevive: true` or `.revive()`). In `ArenaCombatant`, reducing Strength or effectiveMaxHp to 0 sets `currentHp = 0`, logs instant death, and `isAlive` immediately returns `false` (and `isDefeated` returns `true`) whenever `getAbilityScore(AbilityType.strength) <= 0`.
- **Clean Domain Boundaries & Read-Only Repository Invariant:** `CampaignProfile` and `CampaignProfileDto` are strictly decoupled from mutable character migration baggage (`_migratedCharacters` eradicated). Legacy character extraction is handled explicitly via `CampaignProfileDto.extractLegacyCharacters()` at the service boundary. `LocalCampaignRepository.loadAllProfiles()` is strictly read-only and predictable, devoid of character repository write side-effects or synthetic room membership generation.
- **Universal Item Codex & Character Sheet Cross-Loading:** `MagicItemLibrary.allItems` serves as the centralized source of truth synchronized from `HomebrewPersistenceService.syncToLibraries()` (`equipmentItemToMagicItem`). Homebrew items are browsable in `ItemCompendiumScreen`, assignable to any character roster sheet directly via `ItemDetailDialog`, addable within `CharacterSheetController.addItem()`, and selectable in the Character Builder equipment dialog.
- **Universal Fluff & Lore Ingestion Pipeline:** Community compendium fluff bundles and standalone fluff entries are recognized without artificial schema markers. Pure fluff maps infer entity categories from attributes (`className` -> `subclass`), image paths (`bestiary/` -> `monster`), or codex libraries. Two-pass deferred resolution resolves `_copy` references so variant lore and artwork are fully inherited. `IngestionBatchResult` and `HomebrewBundle` carry `List<EntityFluff> fluff`, seamlessly bridging background compute isolate boundaries into `EntityFluffService` and remote repository ingestion.
- **System-Wide Backup Parity & 11-Category Invariant:** All backup services (`DmBackupService`, `AppBackupService`, `HomebrewPersistenceService`) serialize and restore all 11 homebrew categories: `spells`, `monsters`, `items`, `classes`, `subclasses`, `races`, `subraces`, `feats`, `backgrounds`, `otherEntries`, `fluff`. Export logic unifies persistent storage collections with in-memory library custom registries, sweeping attached sub-entities (`c.subclasses`, `r.subraces`) alongside standalone records. Per-item `try-catch` deserialization ensures single malformed records do not discard entire collections.

### 5. Performance & Pre-Computation Directives
- **Zero Runtime Regex in Hot Loops:** Never execute `RegExp` inside combat rounds, Monte Carlo loops, or DPR calculations. Parse traits into precomputed numeric profiles during ingestion.
- **Combat Action Rider AST & ACL Extraction:** Action descriptions are parsed at the ACL ingestion boundary (`StatBlockAclParser.extractRiders`) using pre-compiled regex into strongly-typed `CombatEffectRider` ASTs (`ConditionRider`, `AttributeDrainRider`, `MaxHpReductionRider`, `ForcedMovementRider`, `HealingSupressionRider`, `PeriodicDamageRider`). During combat simulation (`ArenaCombatant.applyAttackHit`), attacks execute composite riders with zero runtime regex, clamping `effectiveMaxHp` and dynamically scaling down attack and saving throw modifiers.
- **Simulation Turn Runner Rider Integration:** `ArenaCombatEngine._resolveSingleAttack` queries precomputed attacks (`attacker.monster.getCombatProfile(edition).attacks`), applies hits via `defender.applyAttackHit`, and forwards `hitResult.riderLogs` directly into `ArenaAttackEvent.appliedRiderLogs` to seamlessly format and append action rider telemetry to `summaryText`.
- **Deterministic Monte Carlo Simulation Seeding:** `DprSimulator.runInIsolate` accepts an optional `seed` parameter and propagates `seed != null ? Random(seed) : Random()` to worker isolates, guaranteeing bit-identical simulation results across repeated runs.
- **Ingestion Concurrency Bounding & Cooperative Yielding:** In `GithubIngestorAdapter`, network downloads are bounded to sequential processing (`concurrentDownloads: 1` by default) with cooperative event-loop yields (`await Future<void>.delayed(Duration.zero)`) between files and stream chunks (`streamChunkSize: 25`), eliminating heap spikes and socket flooding during large remote imports.
- **Copy-On-Write AST Transformations:** `GenericTagScrubber.scrubMap` and `_resolveRefs` enforce copy-on-write semantics, returning the original `Map` or `List` reference unmodified if no child tags or pointers changed to eliminate hundreds of thousands of heap allocations and GC spikes during massive compendium imports.
- **Ledger Suppression & Sliding-Window Error Accumulation:** `HomebrewImportOrchestrator` provides optional ledger suppression (`retainLedger: false`, utilized by `HomebrewExpertOptionsView`) and sliding-window error accumulation (max 100 entries) to prevent heap exhaustion when ingesting tens of thousands of compendium entities.
- **$O(N)$ Batch Fast-Path Persistence:** `HomebrewPersistenceService._saveEntitiesBatchFast` uses a slug-to-index map to merge batches into storage in $O(N)$ time without re-decoding or re-serializing the entire historical database of entities.
- **SharedPreferences OOM Crash Shield:** Both `_saveStringList` and `_saveRawPayloadsBatch` enforce a SharedPreferences OOM shield (skipping mirroring for collections `> 20` items when Hive is open), and `clearAllHomebrew()` invalidates in-memory indexes and purges raw keys across all 11 compendium categories.
- **Monster vs Race Disambiguation & Template Monster Invariant:** In `GithubIngestorAdapter._inferEntityType` and `HomebrewPersistenceService.saveHomebrewEntitiesBatch`, non-generic compendium category hints (`monster`, `monsters`, `bestiary`, `creature`, `npc`) immediately route to `monster`. Compound creature types (`"humanoid (strongheart halfling)"`, `"beast (cat)"`, `"undead (shapechanger)"`) extract and evaluate the primary creature type. Entities possessing monster attributes (`actions`, `action`, `ac`, `hp`, `cr`, `challengeRating`, `hitDice`, `reactions`, `reaction`, `legendary`, `trait`, `isNpc`, `isNamedCreature`, `save`, `passive`) or template clones (`_copy`) strictly reject classification as playable character races. `speed` and `size` alone MUST NEVER classify an entity as a playable race. Non-tabletop crochet patterns and recipes (`recipes.json`, `recipe`, `recipes`, `recipefluff`) are excluded across remote manifest discovery and unpacking. Any discrepancy in statblock traits strictly favors the internal ACL parser (`StatBlockAclParser`).
- **Hexagonal Inversion & Isolate Cold Storage Offloading:** `StorageDurabilityCoordinator` depends strictly on domain port `ICampaignSnapshotSerializerPort` (`serializeToBytes`, `deserializeFromBytes`), completely decoupled from infrastructure `CampaignProfileDto`. `CampaignSnapshotSerializerAdapter` offloads CPU-intensive cold storage serialization (`jsonEncode`) and deserialization (`jsonDecode`) to background isolates via `Isolate.run()`. Multi-megabyte JSON compendium bundles must be processed in background isolates.
- **Storage Durability Sniffing Decoupling & Cold-Storage Rollbacks:** `UserAgentParser` decouples browser sniffing from domain entity `EngineProfile`. `StorageDurabilityCoordinator.hydrateFromColdStorage` verifies constant-time SHA-256 integrity and supports intentional user-initiated `.dndvault` rollbacks without 30-second lookback rejection. `_DangerouslyNerdy5eToolkitAppState.didChangeAppLifecycleState` safely coordinates async storage flushes via error-isolated `flushAll().catchError(...)` to guard against unhandled rejections during background termination.


### 6. Accessibility (a11y) & UI Standards
- **Touch Targets:** All interactive widgets MUST be at least **48x48dp** (`minSize: const Size(48, 48)`).
- **Semantics:** Wrap icons and action triggers in `Semantics` widgets with expanded abbreviation labels (e.g., "STR" -> "Strength", "AC" -> "Armor Class").
- **Dynamic Type Scaling:** All UI must render cleanly without `RenderFlex` overflow errors up to `TextScaler.linear(2.0)`.
- **Reduced Motion:** Wrap intensive animations in `if (!MediaQuery.disableAnimationsOf(context))` checks.
- **Party Room Mobile Responsive Layout:** `_buildActiveCharacterBanner` employs `LayoutBuilder` so the session identity header (`CircleAvatar`, `Expanded(Column('ACTIVE CHARACTER / SESSION IDENTITY', playerName, LinkedBadge))`) spans full width on compact screens (`maxWidth < 620`), while action buttons wrap beneath in a dedicated `Wrap(spacing: 6, runSpacing: 4)`. Dialog titles and card headers wrap text in `Expanded`/`Flexible` widgets with explicit spacing, and compact screen AppBars consolidate secondary icon buttons into popup menus to eliminate `RenderFlex` overflows on mobile screens.

### 7. Legal & SRD Compliance
- **Zero Product Identity:** Prohibited terms: non-SRD proprietary monster names, named lore characters, trademarked lineages, proprietary patrons/subclasses, and trademarked campaign settings. Use generic SRD equivalents only (CC-BY-4.0).
- **Static Compendium IP Sanity Invariant Suite:** `test/infrastructure/compliance/srd_legal_compliance_test.dart` asserts that all bundled static compendiums (`SrdClassesLibrary.allOptions`, `SrdBackgroundsLibrary.allBackgrounds`, `SrdSpeciesLibrary.allSpecies`, `MonsterCodexLibrary.allMonsters`, `MagicItemLibrary.allItems`) contain zero proprietary Product Identity tokens (such as non-SRD campaign settings, trademarked monsters, named wizards, or setting-specific character lineages). Test fixtures must strictly use generic variant lineages (`Human (Lineage of the Forge)`, `CUSTOM_LINEAGE`) instead of proprietary settings or marks.
