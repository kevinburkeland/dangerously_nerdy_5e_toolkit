## 🛡️ Core Engineering Directives

### 1. Hexagonal Architecture & Domain Purity
- **Zero Flutter in Domain:** Files in `lib/domain/` MUST NOT import `package:flutter/...`. Use `package:meta/meta.dart` for annotations like `@immutable`.
- **Enforced via Automated Test:** `test/domain/domain_purity_test.dart` automatically audits `lib/domain/` on every CI run.
- **Infrastructure DTO Purity:** Files in `lib/infrastructure/dtos/` MUST NOT import `package:flutter/...`. Use pure `package:meta/meta.dart` for `@immutable` annotations to preserve decoupling from the Flutter engine runtime. Verified by `test/infrastructure/dtos/dto_purity_test.dart`.
- **Ports & Adapters:** Define abstract interfaces in `lib/domain/ports/`. Implementations live in `lib/infrastructure/repositories/` and `lib/infrastructure/adapters/`.
- **Domain Purity of Transport Ports:** `IP2pTransportPort` and all interfaces in `lib/domain/ports/` must import pure domain contracts (e.g., `TransportState` in `lib/domain/ports/transport_state.dart`) rather than application services (`CascadingTransportRouter`) or infrastructure DTOs (`CharacterTelemetryDto`), strictly preserving the Dependency Inversion Principle.
- **Immutability:** All domain models and value objects must have `const` constructors and `copyWith()` mutators. Never expose mutable lists or maps directly.

### 2. Decentralized State & CvRDT Directives
- **Hybrid Logical Clock (HLC):** Implements `Comparable`. When physical timestamps (`l`) and counters (`c`) collide, use `nodeId` (device ID string) as the deterministic lexicographical tie-breaker. Random tie-breakers are strictly forbidden.
- **Cryptographic Node Identity Enforcement & Uniformity:** Orchestrators and services stamping CRDT registers (including `HomebrewImportOrchestrator` and `PartyRoomService`) must generate pure cryptographically secure UUID v4 fallback identifiers (e.g. via `package:uuid/uuid.dart` `const Uuid().v4()`) rather than physical wall-clock timestamps or prefixed strings to guarantee HLC tie-breaker determinism across simultaneous offline mesh imports. Dynamic node IDs must be resolved once and shared uniformly with internal HLC instances.
- **Clock Spoofing & Skew Mitigation:** Network time synchronization via `INetworkTimePort` and `ClockSyncService` computes physical clock offsets (`offsetMs`). Fallback message queries (such as in `FirebaseFallbackAdapter`) buffer queries by 30 seconds into the past to tolerate physical device clock skew, and enforce bounded SHA-256 payload hash LRU deduplication caches (`_processedPayloadHashes`, max 500 entries) cleared upon disconnection to prevent hash/message ID poisoning.
- **Observed-Remove Set (`CrdtOrSet`):** Deletions create tombstones. Always implement `prune(threshold)` to prevent memory leaks from unbounded tombstone accumulation. Internal items and tombstones maps are strictly sealed via `Map.unmodifiable()` across constructors (`CrdtOrSet`, `const CrdtOrSet.empty()`) and mutator operations (`addBatch`, `remove`, `merge`, `pruneTombstones`).
- **Strict Network Time Injection & Milestone Pruning Decoupling:** Prune tombstones via `RoomStateReconciliationService.executeMilestonePrune` using authoritative server/ledger timestamps, decoupled from unverified local clock estimations. `RoomStateReconciliationService` requires constructor injection of `networkTimeProvider` (sourced from `ClockSyncService.currentNetworkTimeMs`), eliminating local wall-clock spoofing vulnerabilities during pruning.
- **LWW Register (`CrdtLwwRegister`):** Modifications return a new immutable instance.
- **Minion Immutability in CRDT Collections & Zero Silent Mutations:** Minions and summon entities (`AnimatedObjectInstance`) within `CampaignProfile.roomState.activeMinions` are strictly immutable domain entities. All deprecated in-place mutating methods (`takeDamage`, `heal`, `applyHeal`, `grantTempHp`) and silent empty setters are eradicated. Modifications MUST strictly utilize pure copy-transform methods (`applyDamage`, `applyHealing`, `applyTempHp`).
- **Delta Fast-Forward:** Base room state is hydrated from snapshot milestones, with incremental CRDT deltas reconciled on top via `RoomStateReconciliationService`.
- **Peer-Scoped Ephemeral Signaling Isolation:** WebRTC signaling and mesh adapters must partition tracked signaling documents by peer ID (`_peerTrackedDocPaths`). When an individual peer connection is established or opens its DataChannel, invoke `cleanUpPeerSignaling(peerId)` rather than wiping all room signaling documents (`cleanUpSignalingSession()`), preventing premature deletion of in-flight handshakes in multi-peer rooms.
- **Echo Loop Prevention Mutex & Deep Model Equality:** `RoomSyncOrchestrator` synchronizes inbound packet handling using a formal `Mutex` lock (`_syncMutex.protect()`), eliminating boolean flag data races while ingesting and saving incoming network payloads. Entities participating in state broadcasts (`CampaignProfile`, `PartyPurse`) must implement value equality (`operator ==` and `hashCode`) to eliminate false-change broadcast triggers.
- **Sliding Lookback Window & LinkedHashMap O(1) LRU Deduplication:** `RoomSyncOrchestrator` and `CascadingTransportRouter` enforce a 30-second sliding lookback window and an in-memory 500-entry `LinkedHashMap<String, bool>` LRU cache tracking payload SHA-256 digests. This guarantees $O(1)$ amortized lookup, removal, and re-insertion for exact duplicate suppression and packet jitter tolerance, exposing `Set.unmodifiable(_processedPayloadHashes.keys)` for testing. Unknown or malformed payloads (`UnknownSyncMessage`) are discarded *before* updating the LRU cache to prevent cache-busting attacks and deduplication poisoning.
- **Unconditional Tombstone Recording on Removal:** `CrdtOrSet.remove()` unconditionally records a tombstone even if the item does not currently exist in the local active items map (provided `timestamp.isAfter(currentTombstone)`), preventing late-arriving out-of-order `add` operations from reviving deleted entities.
- **Buffered Milestone Pruning Horizon:** Host milestone flushes (`executeHostMilestoneFlush`) buffer the pruning horizon by subtracting twice the heartbeat TTL (`2 * heartbeatTtl`) from network-synchronized physical time, preserving tombstones for peers experiencing transient reconnects while safely purging ancient tombstones.
- **Asynchronous Stream Emission (Deadlock Prevention):** Reactive broadcast `StreamController`s across persistence repositories and transport services (including `LocalCampaignRepository`, `CascadingTransportRouter._stateController`, `CascadingTransportRouter._payloadController`, `RoomSyncOrchestrator._telemetryController`, `FirebaseFallbackAdapter`, `FirebaseSignalingAdapter`, and `LocalWifiAdapter`) MUST explicitly specify `sync: false`. Asynchronous microtask queue emission prevents re-entrant deadlocks when inbound network synchronization holds mutexes (such as `_syncMutex`).
- **Hexagonal Inversion & Isolate Cold Storage Offloading:** `StorageDurabilityCoordinator` depends strictly on domain port `ICampaignSnapshotSerializerPort` (`serializeToBytes`, `deserializeFromBytes`), completely decoupled from infrastructure `CampaignProfileDto`. `CampaignSnapshotSerializerAdapter` offloads CPU-intensive cold storage serialization (`jsonEncode`) and deserialization (`jsonDecode`) to background isolates via `Isolate.run()`. Similarly, `RoomSyncOrchestrator` depends exclusively on domain port `IRoomSyncPayloadPort` rather than coupling to concrete infrastructure mappers.
- **Narrow Mutex Critical Section & Asynchronous Ingress Persistence:** `RoomSyncOrchestrator` restricts `_syncMutex.protect()` strictly to in-memory state reconciliation, vector clock tracking, and CRDT joins. Disk persistence (`campaignRepo.saveProfileImmediate`) and subsequent repository event dispatches are executed decoupled *outside* the mutex lock, eliminating re-entrant mutex deadlocks and lock starvation.
- **Asynchronous Microtask Payload Dispatch, Deduplication Cache & Timer Teardown:** Inbound transport router payloads (`CascadingTransportRouter._handleIncomingPayload`) enforce an asymmetric bounded LRU deduplication cache (500 entries) with injected `payloadHasher` (SHA-256) to silently drop duplicates while updating LRU order, and dispatch accepted payloads asynchronously via `scheduleMicrotask()` to prevent synchronous re-entrant `_syncMutex` deadlocks when adapters failover or receive inbound frames during broadcast execution stacks. Room re-initialization in `CascadingTransportRouter` must explicitly cancel and nullify prior heartbeat timers (`_heartbeatTimer`, `_fallbackHeartbeatTimer`) before activating new adapters.
- **WebRTC Async Microtask Dispatching:** In `WebRtcMeshAdapter`, `_incomingPayloadsController` is initialized with `broadcast(sync: false)` and DataChannel message arrivals in `_registerDataChannel` are dispatched via `scheduleMicrotask(() { if (!_incomingPayloadsController.isClosed) _incomingPayloadsController.add(text); })` to eliminate synchronous event-loop contention and prevent re-entrant mutex deadlocks.
- **Field-Level Sub-Resource Reconciliation (`RoomStateReconciliationService.reconcileProfile`):** Rather than whole-document LWW overwrite of `CampaignProfile` upon receiving `room_sync_full` payloads, state convergence merges sub-resources independently (notes, party purse, party rosters, active minions keyed by `m.id`, active encounters keyed by `participantId`, room metadata, and change logs). Concurrent edits to `notesRegister` resolve deterministically by favoring the higher HLC timestamp, logging the dropped delta to `changeLog` instead of unbounded string concatenation.
- **Explicit Causality & Outbound Echo Suppression:** Network synchronization packets are stamped with monotonic sequence numbers and originating node ID (`origin_node_id`). Broadcast listeners ignore self-echo payloads and suppress outbound broadcasts during active remote sync transactions via microtask-scoped mutexing (`_isApplyingRemoteSync`).
- **Bi-directional Waterfall Step-Up Recovery & Transport Port Decoupling:** `CascadingTransportRouter` monitors network health and periodically probes higher-tier adapters (`probeHigherTiers()`) via the abstract `IP2pTransportPort.probeViability()` contract, stepping up from fallback cloud channels back to WebRTC mesh when viable without downcasting or leaking concrete adapter implementations.
- **W3C Polite Peer Glare Rollback & Clean Recovery:** WebRTC signaling state machine implements standard polite/impolite glare handling. When signaling collisions occur (`have-local-offer` when receiving remote offer), the polite peer rolls back its local offer (`RTCSessionDescription('', 'rollback')`) and accepts the incoming offer. If rollback fails or throws on platform channels, it invokes `prunePeer(peerId)` and immediately initializes a clean `RTCPeerConnection` to accept the inbound offer without connection tear-down or split-brain channel loss.
- **Combat Encounter Time Synchronization & Clock Skew Immunization:** `CombatEncounterService` accepts an injected `networkTimeProvider` (sourced from `ClockSyncService.currentNetworkTimeMs`), and all encounter mutations (`updateEncounterParticipants`, HP adjustments, condition toggles) generate monotonic HLC timestamps anchored to synchronized network time rather than local wall-clock estimations.
- **Deterministic Monte Carlo Simulation Seeding:** `DprSimulator.runInIsolate` accepts an optional `seed` parameter and propagates `seed != null ? Random(seed) : Random()` to worker isolates, guaranteeing bit-identical simulation results across repeated runs.
- **Clock Skew Inversion & Graceful Pruning Deferral:** `RoomStateReconciliationService.safePrune` evaluates pruning thresholds against monotonic network-synchronized physical time (`INetworkTimePort`). When extreme local clock skew would invert pruning horizons ($threshold \ge networkTime$), pruning is deferred gracefully (returning unpruned set) rather than throwing `StateError`.
- **PN-Counter Currency Convergence, modifyCoin & crdt_purse_delta Protocol:** Party currency denominations in `PartyPurse` converge using CvRDT `PnCounter` (positive and negative tracking per node ID), eliminating scalar Last-Write-Wins overwriting. Individual coin delta mutations (`PartyPurse.modifyCoin(denomination, delta, nodeId: id)`) dynamically route through positive/negative registers. Profile reconciliation in `RoomStateReconciliationService._mergePartyPurse` unconditionally merges coin counters (`local.merge(remote)`) via CvRDT lattice join across all denominations. `RoomSyncOrchestrator` emits targeted high-frequency `crdt_purse_delta` payloads upon currency modifications and directly reconciles inbound purse deltas, avoiding full document dumps on routine currency operations.
- **WebRTC DataChannel Readiness Signaling Gate:** In `WebRtcMeshAdapter`, ICE connection state transitions to `connected` defer ephemeral signaling document deletion until the peer DataChannel is fully open (`RTCDataChannelState.RTCDataChannelOpen`) or ICE state reaches `completed`, preventing premature handshake document deletion on early network phase transitions.
- **Transport Step-Down Failure Threshold & Holdoff Hysteresis:** `CascadingTransportRouter` enforces sequential failure thresholds (`sequentialFailureThreshold = 3`) and holdoff cooldowns (`stepUpHoldoff = 5s`) to eliminate rapid transport flapping between WebRTC and cloud relay adapters.
- **Author-Scoped Signaling Document Cleanup & Wildcard Ephemeral Teardown:** `FirebaseSignalingAdapter` tracks wildcard (`toNodeId: '*'`) and authored signaling documents in `_authoredDocPaths`. Session teardown purges all tracked documents, while peer disconnect cleanup purges only author-owned documents to prevent double-deletion collisions.
- **Storage Durability Sniffing Decoupling & Cold-Storage Rollbacks:** `UserAgentParser` decouples browser sniffing from domain entity `EngineProfile`. `StorageDurabilityCoordinator.hydrateFromColdStorage` verifies constant-time SHA-256 integrity and supports intentional user-initiated `.dndvault` rollbacks without 30-second lookback rejection.
- **5e RAW Unconsciousness vs Death Decoupling:** In `HitPoints`, 0 HP unconsciousness (`isDowned => currentHp <= 0`) is decoupled from permanent death (`isDead`). Standard healing (`heal(amount)`) revives downed actors at 0 HP per 5e RAW, while permanent death from massive damage (excess damage >= maxHp) requires explicit revival (`allowRevive: true` or `revive()`).
- **Domain Canonical Ruleset Consolidation & Standard Cryptography:** Canonical `RulesetEdition` (`lib/domain/rules/ruleset_edition.dart`) serves as the pure domain enumeration with lossless adapters to legacy DTO enums (`DmRulesEdition`, `RulesetVersion`). `StorageChecksum` verifies payload integrity using standard `package:crypto` constant-time digest comparison.
- **Stateless Room Stub Rehydration & 30-Day Lease Auto-Renewal:** In stateless WebRTC and P2P mesh architectures, `PartyRoomService.joinCampaign()` inspects active subcollection presence (`rooms/{code}/nodes` and `rooms/{code}/relay_messages`) before concluding a room is missing, preventing false `"Campaign not found"` errors. Whenever any participant connects (host init, player join, or screen mount), `PartyRoomService.ensureRoomExists`, `FirebaseSignalingAdapter.initialize`, and `FirebaseFallbackAdapter.initializeRoom` rehydrate/touch `/rooms/{roomCode}` with `isStateless: true` and reset the 30-day lease (`expiresAt: now + 30 days`, `lastUpdated: now`) via `SetOptions(merge: true)`. Non-existent rooms without active presence or local DM keys continue to reject cleanly without generating phantom ghost records.
- **2014 Background Import Parity & Outbox Wedge-Immunity:** In 2014 rules, backgrounds do not grant Ability Score Increases (ASIs). `HomebrewEntityDto._validateSrd2014Contract` permits 2014 background JSON from GitHub or community compendiums without `ability`/`asi` fields or with empty/null ability arrays. ASI stripping and validation are strictly handled downstream during character compilation in `CharacterFactory.buildFromDraft` and `CharacterValidationEngine`. All room currency and roster operations (`depositCoins`, `withdrawCoins`, `setActiveCharacter`, `addCharacterToRoster`) use `docRef.set(..., SetOptions(merge: true))` with `roomCode`, `code`, and `campaignName`, preventing Firestore `NOT_FOUND` errors on fresh stateless stubs. `PartyRoomService.flushOutbox` aggregates all pending coin operations across the outbox batch into a single document write to avoid Firestore batch collision exceptions, increments `retryCount` on `PartyOutboxAction`, and purges poison pills after 3 consecutive failures to prevent infinite `Syncing (N)` UI spinning. `clearOutbox(roomCode)` enables immediate outbox resets.
- **Firestore App Check Permissiveness & Outbox Auto-Flushing Parity:** `firestore.rules` gracefully permits unverified App Check tokens (`isAppCheckVerified() { return true; }`) while strictly enforcing all schema bounds (valid room code `^[a-zA-Z0-9_-]{3,32}$`, campaign name length $\le 100$, 64-char hostKeyHash, coin map, and member/roster array caps) so development builds, sideloaded Android devices, and web test environments do not fail with `permission-denied`. `PartyRoomService._queueOutbox` schedules automatic debounced background flushing (`_scheduleAutoFlush`) and re-triggers on transient failures, `PartyRoomScreen._initSyncServices` immediately flushes pending outbox operations on room entry, and `PartyRoomService.joinCampaign` applies a 600ms propagation retry buffer to eliminate false "Campaign not found" race conditions during cross-device join.
- **Party Coin Synchronization, Scalar Priority, & Vault Zero-Wipe Protection:** `PartyPurse.fromMap` must prioritize scalar coin denominations (`cp`, `sp`, `ep`, `gp`, `pp`) over stale PN-counters whenever scalars are present and differ from counter values (e.g. after atomic `FieldValue.increment` writes in Firestore). It must safely parse nested counter maps across any Map subtype without strict `Map<String, dynamic>` casting and re-seed the internal PN-counter (`gpC = PnCounter.withInitialValue(gpVal)`), preventing the UI from remaining locked at stale balances on both local and remote devices. Adapters and transport layers (`FirebaseSignalingAdapter.initialize`, `FirebaseFallbackAdapter.initializeRoom`) as well as non-currency campaign operations (`ensureRoomExists`, `joinCampaign`, `linkCharacterToCampaign`, `updateMemberPurse`, `removeCharacterFromRoster`, `updateCharacterRoster`) MUST NEVER transmit or overwrite `partyPurse` in Firestore, preventing room lease renewals, WebRTC signaling handshakes, or character joins from resetting the shared vault balance to zero. `PartyRoomService.streamSession` unifies optimistic local emissions (`_emitSession`) and Firestore snapshot subscriptions through `_sessionControllers[clean]`, providing instantaneous zero-latency UI updates upon user action while keeping remote devices synchronized in real time.
- **Vault Fund Dispersal vs External Loot & CvRDT Lattice Join Idempotence:** Dispersing coins from the shared Party Vault reserve (`isVaultDispersal: true` via `PartyRoomService.disperseCoinsToParty` and `DisperseLootDialog.show`) is a zero-sum reallocation that MUST withdraw character shares from `partyPurse` via `withdrawCoins(...)`, strictly conserving total party wealth without monetary inflation. External loot hoards (`isVaultDispersal: false`) deposit reserve shares and remainders as newly discovered treasure. In `PartyPurse.fromMap`, scalar adjustments differing from PN-counters apply deterministic incremental deltas on `nodeId: 'cloud'` rather than overwriting the counter or inventing uncoordinated node IDs, guaranteeing CvRDT lattice join idempotence ($A \sqcup A = A$) and preventing exponential balance compounding across sync intervals.

### 3. Dual-Ruleset Awareness (2014 RAW vs 2024 Revised)
- The engine supports both **2014 (SRD 5.1)** and **2024 (SRD 5.2)** D&D mechanics.
- Always check or pass the `DmRulesEdition` enum (`DmRulesEdition.dnd2014` vs `DmRulesEdition.dnd2024`) or inspect `RulesetContext`.
- Key differences:
  - Drinking Potions: Action (2014) vs Bonus Action (2024).
  - Exhaustion: 6 discrete tiers (2014) vs 10 linear -2 penalty steps (2024).
  - Counterspell: Spell save DC check (2014) vs CON saving throw by caster (2024).
  - Cure Wounds / Healing Word: 1d8/1d4 (2014) vs 2d8/2d4 (2024).
  - GWM / GWF: -5/+10 & reroll 1s/2s (2014) vs +PB damage & floor 3 (2024).
  - Weapon Masteries: Absent in 2014; active in 2024.

### 4. Anti-Corruption Layer & Data Safety
- **DTO Isolation:** Network/Disk JSON must map to DTOs in `lib/infrastructure/dtos/` before conversion to Domain models.
- **Fault-Tolerance:** Missing or malformed keys must deserialize into safe tabletop defaults without throwing uncaught exceptions.
- **Unparsed Payload Preservation:** Always preserve unrecognized JSON keys in an `unparsedPayload` map to avoid discarding custom homebrew attributes during round-trip serialization.
- **Strict Bounds Clamping:** All numeric stats must be clamped (HP `0..999`, Level `1..20`, Ability Scores `1..30`, Currency `>= 0`).
- **Deserialization Priority:** Computationally normalized or resolved fields (e.g., spatial range and variable damage math) must strictly take precedence over raw fallback JSON keys during DTO deserialization.
- **Strict Entity Resolution & Anti-Collision:** Resolvers and codex lookups must prioritize exact `==` equality matches first. Substring fuzzy matching (e.g. `.contains('plate')`) is strictly prohibited to prevent collision regressions (such as Breastplate inheriting Full Plate AC 18). Fallbacks must enforce word-boundary regex (`\b`) and disallow binding generic tokens (e.g. `'Dragon'`) to distinct compound boss monsters (`'Dragon Turtle'`).
- **Compendium Deduplication & Clean Ingestion:** `SrdEquivalenceIndex` indexes base SRD libraries (`SpellbookLibrary.srdSpells`, `SrdClassesLibrary.baseClasses`, etc.) unpolluted by custom homebrew. Batch imports drop canonical SRD duplicates (`excludeSrdCanon: true`), route `baseitem`/`magicvariant` to items and `subrace` to races, format markdown tables and deities, and persist re-parsed data to both Hive and SharedPreferences.
- **Innermost Tag Resolution & Table Box Formatting:** `EntryNodeTransformer` and `CompendiumJsonIngestionPipeline.cleanRawTags` resolve innermost tags first using `[^{}]+` within a bounded loop (`passes < 10`) to cleanly process nested callout notes (`{@note ... {@spell contagion}}`). Table cells and column headers in `customProperties.rows` and `colLabels` are automatically cleaned to prevent raw unrendered tags (`{@creature ...}`, `{@item ...}`) in rollable table cards and markdown tables. Envelopes containing arrays of tables (such as `names.json`) must be expanded into individual child tables and guarded against stringifying into giant multi-thousand-character corrupted rules.
- **Nested Species Ability Parsing & Comprehensive Bundle Export:** `HomebrewEntityDto._detectEntityType` classifies subraces and entries containing `raceName` or `subrace` as `'race'`. `_extractSpeciesAbilities` parses nested compendium ability arrays, fixed stat bonuses, and choice blocks (`choose: { from: [...], count: ... }`) into `normalizedData['abilities']` and `normalizedData['flexibleAbilities']` without data loss. `HomebrewPersistenceService.exportBundle` and `exportHomebrewBundle` serialize all active homebrew registries (`races`, `subraces`, `classes`, `subclasses`, `backgrounds`, `feats`, `items`, `spells`, `monsters`, `otherEntries`) into sibling arrays.
- **System-Wide Backup Parity & Subrace Reconciliation:** `DmBackupService`, `AppBackupService`, and `HomebrewPersistenceService` serialize and restore all potential homebrew categories (`spells`, `monsters`, `items`, `classes`, `subclasses`, `races`, `subraces`, `feats`, `backgrounds`, `otherEntries`). Bundle and snapshot hydration (`HomebrewBundle.fromMap`, `importFullBackupJson`, `restoreFullSystemSnapshot`) reconciles standalone subraces with parent races and generates shell races for orphan subraces referencing base SRD species.
- **Subrace Character Builder Integration & Custom Lineage Retention:** Character drafts track `subraceRef` (`EntityReference`), validated in `CharacterBuilderScreen` and resolved through `SkillTraitResolver.getSpeciesTraits(subraceSlug: draft.subraceRef?.slug)`. Subraces attached to SRD canon are indexed in `SrdSpeciesLibrary.customSubraces` and gathered during bundle exports to ensure zero loss of species lineages. Subrace selection UI wraps list items in `Material(color: ..., shape: RoundedRectangleBorder(...))` (without conflicting `borderRadius`) to prevent Flutter background assertions.
- **Universal Item Codex & Character Sheet Cross-Loading:** `MagicItemLibrary.allItems` serves as the centralized source of truth synchronized from `HomebrewPersistenceService.syncToLibraries()` (`equipmentItemToMagicItem`). Homebrew items are browsable in `ItemCompendiumScreen`, assignable to any character roster sheet directly via `ItemDetailDialog`, addable within `CharacterSheetController.addItem()`, and selectable in the Character Builder equipment dialog.
- **Universal Fluff & Lore Ingestion Pipeline:** Community compendium fluff bundles (`monsterFluff`, `spellFluff`, `itemFluff`, `raceFluff`, `classFluff`, `subclassFluff`, `featFluff`, `backgroundFluff`, `optionalfeatureFluff`, `conditionFluff`, `rewardFluff`, `objectFluff`, `vehicleFluff`, `trapFluff`, `languageFluff`, etc.) and standalone fluff entries are ingested without artificial schema markers. Pure fluff maps infer entity categories from attributes (`className` -> `subclass`, `raceName` -> `race`), image paths (`bestiary/` -> `monster`), or codex libraries. Two-pass deferred resolution resolves `_copy` references so variant lore and artwork are fully inherited. `IngestionBatchResult` and `HomebrewBundle` carry `List<EntityFluff> fluff`, seamlessly bridging background compute isolate boundaries into `EntityFluffService` and remote repository ingestion.
- **SRD Index Decoupling, Subrace & Fluff Persistence Parity, and Resilient Deserialization:** `SrdEquipmentLibrary.baseEquipmentItems` decouples canonical SRD equipment from dynamic `MagicItemLibrary` additions, ensuring `SrdEquivalenceIndex` never misidentifies custom homebrew items as SRD canon or drops them during `reparseAllHomebrew`. `HomebrewPersistenceService` provides full persistence parity for `subraces` (`_keyHomebrewSubraces`, `loadCustomSubraces`, `saveCustomSubracesBatch`) and `fluff` (`_keyHomebrewFluff`, `loadCustomFluff`, `saveCustomFluffBatch`), preserving standalone subraces and lore during imports, reparse operations, and bundle exports. Subrace batch ingestion links into custom parent races when non-SRD species are referenced while preventing empty SRD parent race stubs. All persistence loading methods wrap individual entity deserialization in per-item `try-catch` blocks, guaranteeing that single malformed records log warnings without discarding entire collections.
- **Rolling vs Data Table Differentiation & Tabular UI Rendering:** Compendium tables are classified into `HomebrewOtherCategory.tables` (Rollable Tables) vs `HomebrewOtherCategory.dataTables` (Data & Reference Tables) using `isRollingTable`, inspecting dice indicators in `colLabels` (`d\d+`, `d%`, `roll`, `die`, `dice`), numeric ranges in `rows` (`01-20`, `1-4`), and dice schema properties. Both types sync to `DmScreenLibrary` and appear in the Rules Compendium with interactive subcategory filter chips (`All Tables`, `Rollable Tables`, `Data & Reference Tables`). Markdown tables (`| ... |`) inside rule cards (`DmRuleCard`) are grouped and rendered as native, horizontally scrollable Flutter `Table` widgets via `FormattedMarkdownText` instead of unstructured bullet points. To prevent horizontal `RenderFlex` overflow under narrow viewports (320–352px) or 2.0x dynamic type scaling, card badges (`Rollable`, `Data Table`, `Homebrew`, `EditionDiffBadge`) MUST be grouped inside the subtitle `Wrap` within an `Expanded` column rather than placed as unconstrained siblings in the top-level card `Row`.
- **Monster Feature ACL Discrepancy Resolution & Non-Tabletop Filtering:** Remote manifest discovery and bundle unpacking explicitly ignore non-tabletop crochet patterns and recipes (`recipes.json`, `recipe`, `recipes`, `recipefluff`). Monster features, actions, and combat traits parsed at the ingestion boundary and hydrated into `MonsterCombatProfile` or `CompendiumGenericEntryParser` must be evaluated against the internal ACL parser (`StatBlockAclParser.parseMonsterFeature` and `StatBlockAclParser.parseStatBlockBoundary`). Whenever an incoming raw statblock declaration conflicts with the internal ACL parser (such as mobility capabilities `canFly`, `canSwim`, `canClimb`, `canBurrow`, `hasHover`, melee/ranged reach, saving throw proficiencies, spell save DC, spell attack bonuses, or action riders), the resolution MUST strictly favor the internal ACL parser.
- **Markdown Table Parsing & Detail Dialog Parity:** `FormattedMarkdownText` isolates markdown tables from touching paragraphs via `_isolateMarkdownTables`, normalizes uneven rows to `maxCols` to prevent fatal Flutter `Table` assertion errors, preserves escaped pipes `\|` within cells, and applies zebra-striped styling with horizontal scroll. Detail and comparison views (`DmRuleComparisonDialog._buildRuleWidgets`) group consecutive `|` lines and delegate to `FormattedMarkdownText` instead of prepending raw pipe rows with bullet points.
- **Universal Compendium & Codex Markdown Formatting (`FormattedMarkdownText`):** All compendium cards and detail dialogs (`ItemCard`, `ItemDetailDialog`, `SpellCard`, `SpellComparisonDialog`, `CreatureStatBlockDialog`, `FeatCard`, `HomebrewStudioScreen` preview dialog, `CharacterBuilderScreen`, and `AddFeatDialog`) MUST use `FormattedMarkdownText` to render formatted descriptions and embedded markdown tables rather than plain Flutter `Text`. When rendering line-capped previews on card surfaces, `FormattedMarkdownText` supports `maxLines` and `overflow` (e.g. `TextOverflow.ellipsis`) to cleanly display bold/italic inline text and handle multi-block previews.
- **Subrace Attribute Replacement, Skill, & Spell Ingestion, & Markdown Formatting:** `Subrace` preserves all mechanical attributes (`abilityScoreSummary`, `fixedAbilityBonuses`, `flexibleAbilityCount`, `flexibleAbilityBonus`, `speed`, `darkvision`, and `grants`). `CompendiumRaceParser.parseSubrace` normalizes ability keys to standard lowercase names (`dexterity`, `intelligence`, etc.) and extracts skills, tools, and bonus spells from `skillProficiencies`, `additionalSpells`, and `trait`/`entries`. In 2014 mode, subrace attributes REPLACE base species attributes rather than adding to them: when a subrace specifies ability score increases (e.g. High Elf `+2 DEX, +1 INT`, Mountain Dwarf `+2 CON, +2 STR`, or variant lineage subraces), walking speed (e.g. Wood Elf 35 ft), or darkvision (e.g. Drow 120 ft), `CharacterBuilderScreen` and `AbilityScoreStep` replace the base species values with the subrace's values. Innate cantrips and spells from subraces/species (`SkillTraitResolver.getInnateSpeciesSpells`) are auto-registered upon character finalization, and subrace skill proficiencies are passed to `SkillTraitResolver.resolveSkills` with collision detection. All subrace descriptions across `CharacterBuilderScreen`, `RaceCard`, and `RaceDetailDialog` MUST be rendered using `FormattedMarkdownText` with structured attribute badges (`+2 DEX, +1 INT`, `Speed 35 ft.`, `Darkvision 120 ft.`) rather than plain, regex-stripped text.
- **Action Rider Execution, Subrace Pool Constraints, & Background Compilation:** Attack actions and spells extract condition saving throw riders (`ConditionRider`, knockdown prone) with dynamic fallback DC calculation ($8 + \text{PB} + \text{AbilityMod}$). `ArenaCombatant.applyAttackHit` executes saving throw checks, manages HP via domain `HitPoints`, and appends formatted pass/fail condition logs to `ArenaAttackEvent.summaryText`. Subrace flexible choices are bounded by `flexibleAbilityPool`, preventing unselected choices from defaulting to Strength in 2014 mode. Background skills, starting equipment instances, and 2024 ASIs are normalized and granted onto compiled characters by `CharacterFactory.buildFromDraft()`.
- **Shadow Strength Drain & Instant Death Hardening:** `StatBlockAclParser.extractRiders` parses `AttributeDrainRider` with `deathAtZero: true` on regex variations of `dies if this reduces (?:its\s+)?(?:Strength|ability|score)? to 0`. In `ArenaCombatant`, reducing Strength or effectiveMaxHp to 0 sets `hitPoints = hitPoints.copyWith(currentHp: 0)`, logs `"$displayName's ${targetAbility.shortName.toUpperCase()} was reduced to 0! $displayName dies instantly!"`, and `isAlive` immediately returns `false` (and `isDefeated` returns `true`) whenever `getAbilityScore(AbilityType.strength) <= 0`.
- **Subrace Fixed & Flexible ASI Compilation:** In 2014 mode, `CharacterDraft.reconcile()` reconciles `pendingFlexibleAbilityChoices` strictly against `subraceRef.flexibleAbilityPool` without defaulting to Strength, and computes `speciesBonusScores` (base species fixed bonuses + subrace fixed bonuses + selected flexible choices), enforcing `backgroundBonusScores = AbilityScores.zero()`. `CharacterValidationEngine.reconcileDraft` preserves `bonusScores = updated.speciesBonusScores` instead of zeroing it.
- **2014 Background Ingestion & Starting Equipment/Feature Injection:** `SrdBackgroundsLibrary.findBySlug` returns hydrated `Background` instances with canonical 2014 skill proficiencies, starting equipment items (`extractStartingEquipment`), and narrative background features (`get2014Feature`, e.g., 'Shelter of the Faithful' for Acolyte). During `CharacterFactory.buildFromDraft`, 2014 backgrounds grant skill proficiencies, instantiate starting equipment into `character.inventory` (unless `draft.takesStartingWealth` is true), and inject narrative background features into `character.customProperties['backgroundFeature']` without polluting `character.feats` or generating background ASIs.
- **Lineage Spell Grant Extraction & Artificer Starting Tool Proficiencies:** `FeatureGrant.extractBonusSpells` and `CompendiumRaceParser._extractGrants` comprehensively extract spells from `additionalSpells` across `innate` (including nested `daily` maps), `prepared`, `known`, and `expanded` (spell slot mapping `s1`..`s5`), detecting cantrip flags (`#c`) to populate `FeatureGrant.bonusSpell(isCantrip: true)`. `SkillTraitResolver.getInnateSpeciesSpells` resolves prefix-stripped subrace slugs, differentiates character level (`innate`, `known`, `prepared`) from spell slot level (`expanded`), and `CharacterFactory.buildFromDraft` auto-merges species/subrace cantrips into `character.cantrips` and innate/expanded spells into `character.spellsKnown`. `SkillTraitResolver.resolveTools` guarantees Artificer starting tool proficiencies (`Thieves' Tools`, `Tinker's Tools`, and artisan tools) and background tools during `CharacterFactory.buildFromDraft` and `CharacterDraft.reconcile`. In `CharacterBuilderScreen._buildClassToolsPrompt`, an Artificer prompt allows selecting an artisan's tool choice while displaying granted tools, and `_buildStepSpells` includes expanded species spells in class spell choices.
- **Storage Durability & Eviction-Immunity Architecture:** Pure domain models in `lib/domain/storage/models/` (`EngineProfile`, `StorageTelemetryReport`, `StorageSnapshotBundle`) and port contracts (`IStorageDurabilityPort`, `IPhysicalSnapshotPort`) must maintain zero Flutter dependencies. `EngineProfile` classifies browser engines and OS using deterministic token substring matching without regular expressions, accurately identifying WebKit 7-day eviction risks (`isWebKitEvictionRisk`) and Firefox gesture fences (`requiresExplicitGesture`). `StorageDurabilityCoordinator.executeSilentPreflight()` runs prior to IndexedDB/Hive connection pool initialization to prevent browsers from locking storage into ephemeral tiers, suppressing boot prompts on Firefox Desktop while silently requesting persistence on Chromium and WebKit Standalone PWAs. `StorageSnapshotBundle` seals cold-storage backups with pure Dart constant-time SHA-256 verification against `SHA-256(vaultId + payloadBytes)`. Hydration validates timestamps against a 30-second sliding lookback window to prevent stale snapshots from overwriting fresh local CRDT vectors. `StorageSnapshotBundle` enforces zero-loss ingestion parity across all homebrew and official categories. `StorageDurabilityBanner` enforces a zero-friction invariant (hidden when persisted or standalone PWA), displaying non-modal dismissible warnings for Safari tabs and high-contrast alerts for storage pressure $\ge 80\%$ with WCAG 48x48dp touch targets and 2.0x Dynamic Type scaling. PWA app shell cache shield (`web/service_worker.js` and `web/sw.js`) applies immutable cache-first caching to app shell assets (`index.html`, `flutter.js`, `main.dart.js`, `canvaskit/*`, wasm binaries) while strictly excluding APIs and dynamic websocket streams to preserve IndexedDB authority.
- **Compendium Class Starting Skills & Attributes-First Flexible Lineage Architecture:** `CompendiumClassParser.parseClassSkills` and `CommunityCompendiumAdapters.parseClass` parse community compendium schemas (`startingProficiencies.skills`, `choose.from`, `any`, lists, `{@skill}` tags) into `customProperties['allowedSkills']` and `customProperties['skillChoiceCount']`. `CharacterClass` exposes domain getters `allowedSkills` (falling back safely to all skills) and `skillChoiceCount` (defaulting to 2). In `CharacterDraft.reconcile()`, `pendingFlexibleAbilityChoices` adds to `speciesBonusScores` for base species (`speciesRef`) as well as subraces (`subraceRef`), honoring `flexibleAbilityPool`. In `CharacterBuilderScreen`, when stats are allocated prior to species (`attributesFirst` preset or navigation), selecting a lineage with flexible choices (Half-Elf, Variant Human, Custom Lineage) renders the flexible choices prompt inline directly inside the selected species card with a live attribute score total preview and gates progression until choices are made. In standard wizard flow where species precedes stats, flexible choices can be selected at the species step or finalized at the ability scores step without blocking early progression.
- **5e RAW Value Object Healing, Skill Choice Invariants, & Crit Riders:** `HitPoints.heal()` requires explicit revival semantics (`allowRevive: true` or `.revive()`) to restore hit points to an actor at 0 HP / dead, preventing unconscious/dead actors from reviving via standard healing in unit tests and combat resolution. In `CharacterValidationEngine.calculateSkillRefunds()`, class skill choice pools allow selecting alternative skills without triggering improper skill refund collisions; only fixed auto-granted proficiencies trigger skill refunds. On critical hits, `PeriodicDamageRider.rollDamage()` doubles damage dice (`diceCount * 2`) without doubling flat bonuses, and `DprSimulator` cleanly executes critical rider rolls.
- **Clean Domain Boundaries & Read-Only Repository Invariant:** `CampaignProfile` and `CampaignProfileDto` are strictly decoupled from mutable character migration baggage (`_migratedCharacters` eradicated). Legacy character extraction is handled explicitly via `CampaignProfileDto.extractLegacyCharacters()` at the service boundary. `LocalCampaignRepository.loadAllProfiles()` is strictly read-only and predictable, devoid of character repository write side-effects or synthetic room membership generation.
- **Vectorized Reconnection Ordering & Offline Causal Convergence:** `RoomSyncOrchestrator` maintains per-node sequence vector clocks (`_nodeSequenceVectors`) and offline edit tracking, eliminating strict scalar sequence drops (`originSeq <= lastSeq`). Relayed frames and partitioned burst updates reconcile deterministically into state without dropping valid mutations, while preserving the 30-second sliding lookback window (`inboundTimestamp >= localTime - 30000`) and 500-entry LRU SHA-256 deduplication. Envelope JSON serialization is decoupled into `RoomSyncPayloadMapper`.
- **Pure CRDT Room State Reconciliation & Collection Ergonomics:** `RoomStateReconciliationService` eliminates all scalar wall-clock comparisons (`inboundTimestamp >= localTimestamp`). Minions and encounter participants reconcile via `CrdtOrSet` with HLC tombstones, campaign notes converge via `CrdtLwwRegister<String>` (favoring the higher HLC timestamp and logging dropped deltas to `changeLog`), and party currency converges via `PnCounter` lattice joins. Generative `const RoomNodeState` is preserved for compile-time constants and test ergonomics, offering rich collection methods (`length`, `isEmpty`, `isNotEmpty`, `first`, `last`, `[]`, `map`, `where`, `toList`, `iterator`) alongside `RoomNodeState.fromLists` for dynamic `Iterable` inputs.
- **Dedicated Recipient Signaling Mailboxes & Step-Up Probing:** `FirebaseSignalingAdapter` isolates P2P signaling handshakes into dedicated recipient mailboxes (`rooms/{roomCode}/nodes/{toNodeId}/signals/{signalId}`), eliminating wildcard race conditions, cross-peer signal collisions, and premature document deletion in multi-peer topologies. `LocalWifiAdapter.probeViability` implements non-destructive UDP probing with socket re-use to safely assess Tier 1 step-up viability without crashing bound sockets.
- **Persistence Atomicity & Lifecycle Storage Flushes:** `LocalCampaignRepository._persistProfileToDisk` writes campaign profile data and index keys atomically via `AppDatabaseService.putAll`, preventing index desynchronization on unexpected termination. `_DangerouslyNerdy5eToolkitAppState` wires `AppLifecycleListener` for awaited asynchronous storage flushes (`onPause`, `onHide`, `onDetach`, `onExitRequested`) with error isolation.
- **Firestore Security Rules Claim Parity, Schema Resilience & Backward Compatibility:** In `firestore.rules`, room updates permit DMs to set `hostKeyHash` when claiming existing stubs: `(!('hostKeyHash' in resource.data) || resource.data.hostKeyHash == '' || !('hostKeyHash' in request.resource.data) || request.resource.data.hostKeyHash == resource.data.hostKeyHash)`. `firestore.rules` grants deletion on room documents and all subcollections when verified by App Check (`allow delete: if isAppCheckVerified();`). Device timestamp tolerance expands to $\pm 24$ hours to accommodate offline queues and physical device clock drift. `isValidCoinMap` gracefully validates coin bounds without fragile `hasOnly` constraints, permitting historical room test data and web `number` types (`data.gp is int || data.gp is number`). Node and sender identifiers support up to 128 characters (`<= 128`), relay payloads support up to 1MB (`< 1000000`), and a dedicated fallback rule for `/rooms/{roomCode}/signaling/{signalId}` preserves backward compatibility for cached/older browser clients.
- **Automatic Existing Campaign Cloud Sync & Campaign Lifecycle Management:** `PartyRoomService.syncAllExistingCampaignsToFirestore()` iterates all local campaign memberships on `LandingScreen` mount and rehydrates/ensures room stubs on Cloud Firestore with valid codes, campaign names, host key hashes, and party purses. `PartyRoomService.leaveCampaign()` purges local membership, removes player/character from active players and roster in Firestore via `FieldValue.arrayRemove`, logs `playerLeave` audit event, and disposes dice streams. `PartyRoomService.deleteCampaign()` verifies DM authority against `hostKeyHash`, deletes `/rooms/{roomCode}` from Firestore, disposes dice streams, and purges all local state, memberships, loot, and events. Both `LandingScreen` campaign cards and `PartyRoomScreen` AppBar popup menu expose confirmation-guarded Leave Campaign (for players) and Delete Campaign (for DMs) actions.
- **CvRDT PN-Counter Reduction Invariant, Full Character Storage, & Local Persistence Priority:** In `PartyPurse`, all reductions to coin balances (via `setCoins`, `modifyCoin`, or `copyWith`) MUST calculate the delta against `effectiveCounter` and record negative decrements (`counter.decrement(nodeId, delta)`) rather than re-seeding the counter with a positive scalar via `PnCounter.withInitialValue(val)`, which previously caused balances to monotonically snap back to historical maximums on CvRDT merges. In `PartyRoomService`, `session.sharedCharacters` must store the full `character.toMap()` payload rather than truncated `CharacterTelemetryDto.toMap()`, preventing `CharacterResourcePool` from resetting to 10 HP. `Character.toMap()` explicitly includes `maxHp`, `currentHp`, `tempHp`, and `armorClass`, while `Character.fromMap()` and `CharacterResourcePool.fromMap()` defensively fall back to top-level `hp`/`currentHp` and `thp`/`tempHp`. UI consumers opening character sheets in party rooms must check local persistent storage (`CharacterPersistenceService.getCharacter`) first before remote `session.sharedCharacters`, and push updated telemetry and member purses back to the party room on route return. `LocalCharacterRepository` maintains zero unsynchronized in-memory caches, persisting immediately and synchronously mirroring to both Hive and `SharedPreferences` for complete read-after-write consistency across services.
- **Homebrew Feat Proficiencies, Class Skills Ingestion, Pipe-Delimited Feature Fallbacks & Combat Action Propagation:** `CompendiumFeatParser`, `HomebrewEntityDto`, and `FeatureGrant.bonusTool` / `armorProficiency` parse and retain `armorProficiencies`, `toolProficiencies`, and `weaponProficiencies`. In `CharacterSheetController.addFeat()` and `removeFeat()`, tool choices and fixed tool grants are applied directly to `_character.toolProficiencies`, while armor and weapon proficiencies are re-resolved via `SkillTraitResolver.resolveArmorProficiencies` and `resolveWeaponProficiencies` across class, species/subrace, feats, and custom properties. `AddFeatDialog` dynamically detects tool choices (`anyArtisansTool: 1`, `any: 1`, or text) to display a tool dropdown and granted proficiencies banner. In community compendium format, `raw['proficiency']` contains saving throws (`['con', 'int']`), NOT starting skills. Both `CompendiumClassParser.parseClassSkills` and `HomebrewEntityDto._extractClassSkills` explicitly guard against confusing saving throws with starting proficiencies, extracting skills only from `startingProficiencies.skills` (or archetype fallback pools for sidekicks/artificers) to prevent homebrew classes from improperly defaulting to all 18 skills. Community compendium class features exported as `Name|Class|Source|Level` are parsed in `CompendiumClassParser`, `FeaturesTraitsSection`, and `ClassDetailDialog` using well-known mechanic fallbacks (`Helpful`, `Cunning Action`, `Second Wind`, `Infuse Item`, `Magical Tinkering`, etc.), displaying rich descriptions and level badges instead of unformatted book references. `CharacterActionsResolver._extractActionsFromMarkdown` and `_extractActionsFromJson` parse pipe-delimited feature strings, level-gate them against the character's class level, map recognized actions to their corresponding `ActionType` (bonus action, action, reaction, special), and populate `CharacterCombatAction` with full descriptions. `LanguagesToolsSection` renders an **Armor & Weapon Proficiencies** card right below Tool Proficiencies, displaying dynamic chips for all active armor, shield, and weapon proficiencies.




### 5. Performance & Pre-Computation
- **Zero Runtime Regex in Hot Loops:** Never execute `RegExp` inside combat rounds, Monte Carlo loops, or DPR calculations. Parse traits into precomputed numeric profiles during ingestion.
- **CvRDT Ledger Batching & Import Throughput Optimization:** `CrdtOrSet.addBatch` replaces sequential single-item additions to eliminate $O(N^2)$ map re-allocations during compendium streaming. `HomebrewImportPreviewDialog` pre-buckets compendium categories once during analysis, restricts `initiallyExpanded` to lists with `<= 50` items to eliminate initial widget tree explosion, and throttles `onProgress` `setState` updates to at most once per 50 items or 80ms. `SrdEquivalenceIndex.build()` checks `isBuilt` to prevent redundant index rebuilds on every chunk of 50 entities.
- **Combat Action Rider AST & ACL Extraction:** Action descriptions are parsed at the ACL ingestion boundary (`StatBlockAclParser.extractRiders`) using pre-compiled regex into strongly-typed `CombatEffectRider` ASTs. During combat simulation (`ArenaCombatant.applyAttackHit`), attacks execute composite riders (`ConditionRider`, `AttributeDrainRider`, `MaxHpReductionRider`, `ForcedMovementRider`, `HealingSupressionRider`, `PeriodicDamageRider`) with zero runtime regex, clamping `effectiveMaxHp` and dynamically scaling down attack and saving throw modifiers.
- **Simulation Turn Runner Rider Integration:** `ArenaCombatEngine._resolveSingleAttack` resolves attacks by querying precomputed attacks (`attacker.monster.getCombatProfile(edition).attacks`), applying attack hits via `defender.applyAttackHit` with defensive modifier callbacks, and forwarding `hitResult.riderLogs` directly into `ArenaAttackEvent.appliedRiderLogs` to seamlessly append saving throws and condition outcomes to `summaryText`.
- **Class Skill Choice Ingestion, Signaling Path Consistency, & DPR Rider Simulation:** `HomebrewEntityDto._detectEntityType` recognizes classes by signature keys (`hitDie`, `classFeatures`, `startingProficiencies`). `_normalizeAndClamp` parses nested `startingProficiencies.skills`, `proficiencyChoices`, natural language choices ("Choose 2 from..."), and flat skills arrays into `normalizedData['skillProficiencies']` and `normalizedData['flexibleSkills']`, while adding all class keys to `recognizedKeys` to prevent unparsed payload leakage. `HomebrewIngestor.mapClassFromDto` maps DTOs into domain `CharacterClass` / `ClassDefinition`. `FirebaseSignalingAdapter._sendSignal` defers recording tracked paths in `_peerTrackedDocPaths` until Firestore `doc().set()` succeeds cleanly, preventing phantom document paths on failed network writes. `DprSimulator.run()` evaluates ongoing damage and numeric attribute drain from `PeriodicDamageRider` and `AttributeDrainRider` on landed hits without intermediate heap allocations, accurately reflecting rider contributions in mean damage and DPR. `_DangerouslyNerdy5eToolkitAppState.didChangeAppLifecycleState` safely coordinates async storage flushes via error-isolated `flushAll().catchError(...)` to guard against unhandled rejections during background termination.
- **Background Isolates:** Multi-megabyte JSON compendium bundles must be processed in background isolates.

### 6. Accessibility (a11y) & UI Standards
- **Touch Targets:** All interactive widgets MUST be at least **48x48dp** (`minSize: const Size(48, 48)`).
- **Semantics:** Wrap icons and action triggers in `Semantics` widgets with expanded abbreviation labels (e.g., "STR" -> "Strength", "AC" -> "Armor Class").
- **Dynamic Type Scaling:** All UI must render cleanly without `RenderFlex` overflow errors up to `TextScaler.linear(2.0)`.
- **Reduced Motion:** Wrap intensive animations in `if (!MediaQuery.disableAnimationsOf(context))` checks.
- **Party Room Mobile Responsive Layout:** `_buildActiveCharacterBanner` employs `LayoutBuilder` so the session identity header (`CircleAvatar`, `Expanded(Column('ACTIVE CHARACTER / SESSION IDENTITY', playerName, LinkedBadge))`) spans full width on compact screens (`maxWidth < 620`), while action buttons wrap beneath in a dedicated `Wrap(spacing: 6, runSpacing: 4)`. Dialog titles and card headers wrap text in `Expanded`/`Flexible` widgets with explicit spacing, and compact screen AppBars consolidate secondary icon buttons into popup menus to eliminate `RenderFlex` overflows on mobile screens.

### 7. Legal & SRD Compliance
- **Zero Product Identity:** Prohibited terms: non-SRD proprietary monster names, named lore characters, trademarked lineages, proprietary patrons/subclasses, and trademarked campaign settings. Use generic SRD equivalents only (CC-BY-4.0).
- **Static Compendium IP Sanity Invariant Suite:** `test/infrastructure/compliance/srd_legal_compliance_test.dart` asserts that all bundled static compendiums (`SrdClassesLibrary.allOptions`, `SrdBackgroundsLibrary.allBackgrounds`, `SrdSpeciesLibrary.allSpecies`, `MonsterCodexLibrary.allMonsters`, `MagicItemLibrary.allItems`) contain zero proprietary Product Identity tokens (such as non-SRD campaign settings, trademarked monsters, named wizards, or setting-specific character lineages). Test fixtures must strictly use generic variant lineages (`Human (Lineage of Artifice)`, `CUSTOM_LINEAGE`) instead of proprietary settings or marks.
